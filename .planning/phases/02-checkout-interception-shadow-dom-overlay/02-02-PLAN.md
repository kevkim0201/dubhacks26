# Plan 02-02: Frontend Client Integration & Checkout Triggering

## Objective
Implement the frontend client helper `fetchRecommendations(cartData)` and integrate it into the content script detection loop when checkout score $\ge 5$.

## Tasks

### 1. Add `fetchRecommendations` Helper (`extension/src/lib/checkout-api.js`)
- Import `apiFetch` from `./api.js`.
- Format cart data:
  ```javascript
  export async function fetchRecommendations(cart) {
    const rawTotal = String(cart?.total ?? "").replace(/[^0-9.]/g, "") || "0";
    const items = (cart?.items ?? []).map((item) => ({
      name: typeof item === "string" ? item : item.name || "Item",
      price: typeof item?.price === "number" ? item.price : parseFloat(String(item?.price || "0").replace(/[^0-9.]/g, "")) || 0,
      quantity: item?.quantity || 1,
    }));

    return apiFetch("/api/checkout/recommendations", {
      method: "POST",
      body: JSON.stringify({
        items,
        total_cost: parseFloat(rawTotal),
        store_domain: cart?.store || location.hostname,
      }),
    });
  }
  ```

### 2. Trigger on Checkout Detection (`extension/src/content/index.js` & `detect.js`)
- When `scoreCheckout(document)` reaches threshold $\ge 5$:
  - Read cart items and total via `readCheckout()`.
  - Check if recommendations for this cart/hostname are already cached in session storage to avoid duplicate network calls.
  - Asynchronously fetch recommendations: `fetchRecommendations(checkout)`.
  - Store recommendations on `activeCheckout.recommendations` and re-render the overlay with Pip's Swaps.

### 3. Handle Auth & Offline Graceful Degradation
- If user is not yet logged in or if backend is offline, catch error cleanly without crashing detection or blocking the standard checkout overlay.

## Verification
- Test checkout detection on demo store (`http://localhost:8000/demo/`).
- Verify in browser DevTools Network tab that `POST /api/checkout/recommendations` is dispatched upon reaching checkout and returns 2–3 products.
